MacBedrock / Pull request walkthrough

Prepare a Windows ARM environment for Microsoft Store Bedrock

A native Mac companion builds a dedicated Windows VM so the player can use the Minecraft purchase on their Microsoft account.

01 / How it works

Give the Windows purchase a Windows environment.

Before: The official Mac launcher has no Bedrock client. An Android launcher requires a separate Google Play purchase and cannot use Microsoft Store ownership.
01 / PREPARE

MacBedrock

Verify the user’s Microsoft ISO. Install the pinned, notarized UTM engine. Create a private VM bundle.

02 / VIRTUALIZE

UTM + QEMU

ARM64 hardware virtualization: four cores, 8 GB memory, Secure Boot, TPM, and an 80 GB growing disk.

03 / RENDER

Triton → DXMT

Experimental guest DirectX 11 driver forwards rendering to Metal. Drivers are installed inside Windows.

04 / PLAY

Microsoft Store

The player signs into Windows, installs their owned Minecraft copy, then verifies actual gameplay.

Proven boundary: This Mac’s environment boots normal Windows Setup and has reached the product-key screen. Windows installation, Store authentication, Minecraft, and multiplayer remain unverified.
02 / Decisions & tradeoffs

Make the environment reproducible and recoverable.

Preserve the user’s disk

New files are staged beside the destination, then committed by a same-volume rename. An existing VM is never replaced. APFS clones save installer space; the raw virtual disk allocates space as used.

NAT has no forwarded ports. Host folders, USB, and clipboard sharing start disabled.

Keep normal Windows setup

The upstream driver CD’s automatic answer file caused a setup error and changes account/security defaults. MacBedrock builds manual driver media from an allowlist, preserving driver binaries and their license.

Windows licensing stays separate. MacBedrock never asks for Microsoft credentials.

Respect macOS checks

The engine download is SHA-256 pinned and must pass codesign and Gatekeeper checks. Its notarized signature is preserved. Quarantine remains enabled.

The locally built MacBedrock app is ad-hoc signed; smooth public distribution still requires Developer ID signing and notarization.

Expose the experimental limit

UTM 5.0.5 provides the accelerated path. MacBedrock requests ANGLE Metal and DXMT at engine launch. An already running engine keeps its settings, which the guide tells the player to check.

No DirectX 12, frame-rate, or Minecraft compatibility guarantee is made.

04 / How to verify

Follow the whole installation, not just the button.

swift test
MACBEDROCK_LIVE_INSTALL_TEST=1 swift test --filter testLiveVerifiedInstallationWhenRequested
bash scripts/build-app.sh
open dist/MacBedrock.app
  1. Choose the official Windows 11 25H2 English ARM64 v2 ISO. Create the environment and open it.
  2. In UTM, press Run and respond to the CD boot prompt. Finish normal Windows Setup using the correct Windows license.
  3. If networking needs a driver, choose the ARM64 NetKVM folder on the mounted MacBedrock-Drivers CD.
  4. Run the guest-tools installer, select experimental 3D graphics, and reboot. Confirm DXMT in UTM settings and Direct3D feature level 11_0 in dxdiag.
  5. Sign into Microsoft Store, install the owned Minecraft for Windows copy, create/save/reopen a world, and test audio, input, and multiplayer.
Completed locally: unit tests, release build, real engine download and trust checks, native app handoff, and Windows Setup boot. Still required: Windows license/account steps and a real Minecraft gameplay session.
